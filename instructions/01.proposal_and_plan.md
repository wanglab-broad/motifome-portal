# MIRTO Bilingual Motifome Portal — Proposal & Build Plan

Response to `00.build_idea.md`. Every number below was measured against the real files, not estimated.

---

## 1. Recommendation in one paragraph

Build a **fully static, hash-routed site** generated by one Python bake script: no server, no database, no
runtime. All three requirements are met by precomputed JSON shards read directly by the browser. This is
settled by measurement rather than taste — the decisive number is that the per-nucleotide NTScore, quantized
to `uint8`, costs **1,871 B gzipped per transcript / 33.9 MB for the whole corpus**. Both server-based designs
justified themselves primarily on "288 MB of HDF5 cannot ship to a browser." It can. Once that falls, the only
remaining server capability is an ad-hoc query workbench that no stated requirement asks for.

**Total site: ~114 MB. First paint: 334 KB. Per-gene lookup: one HTTP request, 3.3 KB mean, 1.13 ms.**

Three independent judges — scoring on buildability/survival, scientific value, and interaction design —
each ranked this architecture first (87, 85, 86 / 100) against an API backend (80, 82, 44) and a Dash app
(75, 76, 68).

## 2. The data foundation (verified, not assumed)

These are the facts that decide the design. Each was re-derived independently by an adversarial verifier.

| Fact | Measurement | Consequence |
|---|---|---|
| **Coordinate rule** | `seq[motif_start : motif_end + 1]` reproduces the stored motif string for **889,215 / 889,215 rows (100.000%)**, all three regions. Every rival convention scored ≤0.63%. | The single rule the whole R1 viewer rests on. 0-based, **inclusive both ends**. JS: `seq.slice(s, e+1)`. Make it a build-time assertion that *fails the build*. |
| **Join key** | `refseq_id_without_ver` → **18,093/18,093 (100%)**. `RefSeq mRNA ID` only 91.06%. | Using the wrong column silently drops **1,617 genes**. Dedup first: 1,296 duplicate RefSeq groups, all byte-identical, so dedup is lossless. |
| **Motifs never overlap** | Max stacking depth is **exactly 1** across all 53,367 (transcript, region) groups; 0 overlapping pairs in 835,848 adjacent pairs. | Removes the hardest R1 problem. A flat single-lane span list — no interval packing, no lane assignment, no z-ordering. Only *annotation* tracks need packing. |
| **6% of motifs abut exactly** | 53,729 pairs with gap = 0; **9,838 share a cluster**. | Must give every span its own bordered element, or 9,838 real pairs visually fuse into single false motifs. |
| **Protein motifs project onto the mRNA axis** | `len(cds) == 3×len(protein) + 3` for **19,210/19,210** rows. `mRNA_start = len(utr5) + 3×aa_start`. Verified on ACTB: aa 23–27 `DDAPR` → nt 153–167 → `GACGATGCCCCCCGG`. | **The single highest-value finding.** Puts protein and UTR motifs on one continuous ruler and turns "bilingual" from a caption into a picture. All four candidate designs had drawn three severed axes. |
| **In-transcript coupling is real and rankable** | Co-present gated pairs per transcript: mean 8.04, median 2, p90 23, max 203. **65.2%** of transcripts have ≥1. ACTB has 3, SOX2 33. | Enables the arc layer — "which protein motif in *my* gene pairs with which UTR motif in *my* gene." Costs ~1 KB/shard. No design proposed it. |
| **NTScore exists for both UTRs** | Two HDF5 files; array length == region length for **18,093/18,093** transcripts, 0 mismatches. Domain is **[-8, 0]**. *(Corrected at build time: the minima −7.688 / −7.281 quoted here came from a 1,200-transcript sample. A full scan of all 32,745,544 positions gives −8.0625 utr3 and −8.2500 utr5, so 4 positions — 0.0000122% — clamp to the darkest bin. The domain and the published quantization formula are unchanged; build assertion 10 is restated as a budget and the site discloses the clamp.)* | The R1 headline visual. One survey wrongly declared it unavailable. A [-5,0] quantization silently clips the most model-surprising nucleotides. **No CDS or protein score exists** — render an explicit hatched "not computed" band, never a flat zero line. |
| **Network is small** | 519 nodes / 2,620 edges / max degree 62 / **50.5 KB gzipped**. ~3,658 SVG elements. | Plain SVG with per-element hit-testing. No canvas, no WebGL, no aggregation. |
| **…but it is ONE graph** | **757 edges (28.9%) cross module boundaries.** All 15 module pairs are linked; the 513 module clusters form one giant component. | Drawing six isolated bipartite panels would discard 757 edges — including the manuscript's own M5-protein × M1-UTR observation (192 edges). |
| **`transcript_length` is not mRNA length** | Shorter than `utr5+cds+utr3` in **19,210/19,210** rows (ACTB: 1,059 vs 1,812). | A trap for anyone sizing the viewer from it. Real mRNA length: median 2,923, p99 8,736, max 11,426. |

### Two claims that were REFUTED

**Not every cluster can show a sequence logo.** Only **456 of 900 (50.7%)** have a defensible one. The
on-the-fly fallback does not rescue the rest: clusters were built by k-means on *embeddings*, not sequence —
within a protein cluster 99.5% of member strings are distinct, and the most common 5-mer appears in only 0.5%
of members. A naive PWM has ~4× lower information content, disagrees with STREME on 77% of clusters where both
exist, and manufactures artifacts (`prot_0000`: STREME says `LPALQY`, naive says `TVGGL`; also `SSSSS`,
`PPPPP`, `VVVVV`). **Design the cluster page for the ~50% logo-absent case**, and gate on
`streme.xml test_pvalue < 0.05` — otherwise 43 clusters get a logo built from a motif STREME itself scored
p = 1.0, which is exactly what a reviewer will find.

**Annotation strings cannot be split on commas.** Naive `str.split(',')` damages **41.3% of InterPro rows**
(8,228 of 17,814 InterPro entry names contain a comma — "Zinc finger, C2H2 type") and 6.9% of UniProt rows.
Re-join to the accession tables instead; this also recovers the 32.75% of UniProt features with empty
descriptions that the master table silently dropped. Also: MobiDB/IDPO/SignalP leak onto UTR rows —
**212,449 spurious rows** to mask at bake time.

## 3. Architecture

```
online_contents/
  code/build/                    # Python bake — run once, ~8 min, idempotent
    paths.py                     # THE ONLY file with absolute /Users/... paths
    00_validate.py               # hard assertions; fails the build, not the reader
    01_core.py  02_annotations.py  03_ntscore.py  04_projection.py
    05_coupling.py  06_streme_fill.py  07_cluster_shards.py
    08_network.py  09_modules.py  10_manifest.py
    requirements.txt             # pandas 2.3.3, pyarrow 21.0.0, numpy 1.26.4, h5py 3.11.0, igraph 0.11.6
  portal/                        # the deployable artifact — relative paths ONLY
    index.html  app.css  js/*.js  vendor/  data/**
```

Run: `/opt/anaconda3/envs/bio/bin/python -m build all`

**Baked payloads:** 18,093 gene shards (mean 3.3 KB gz, max 15.2 KB) · 900 cluster shards · network layer
1.6 MB · search index 0.42 MB · NTScore tracks +31.3 MB.

**Ship raw `.json`, not `.json.gz`** — let the host gzip on the wire. Identical repo cost, avoids a silent
decompression failure path.

**Deployment:** GitHub Pages or an S3 bucket under a *lab* account, not a personal one, plus a Zenodo deposit
of the same tree for the DOI printed in the paper. The static tree unzips and runs from a laptop with no
network, which is what makes it still resolve in 2031.

## 4. The three views

### R1 — Gene / transcript view

**Recommended layout: unified mRNA browser stack.** One continuous nucleotide axis carrying all three regions,
with overview + detail linked by a shared viewport — the pattern every reader already knows from IGV/UCSC.

+--------------------------------------------------------------------------------+
| filters [all][M6][annotated][coupled only]  score >-1.0 --o--  alphabet (o)RNA  |
+--------------------------------------------------------------------------------+
| OVERVIEW      widths proportional to real length                               |
|  0        84                                    1212                    1812   |
|  |=5'UTR=|=============== CDS ===================|======= 3'UTR =========|     |

Two render modes per region, chosen by length: **track mode** (canvas NTScore + SVG rects + minimap brush, no
letters) for long regions, **read mode** (60 nt/line, lazily mounted DOM lines) below the threshold. Spans are
drawn per *segment*, not per nucleotide — median 89 segments, max 381 — so the DOM stays small.

*Alternatives considered:* mirrored bilingual (RNA left / protein right with a coupling gutter) for readers
who arrive from the network; reading-first document view for the bench scientist; region-tabbed with sticky
inspector as the low-risk fallback if the projection arithmetic proves troublesome.

### R2 — Motif / cluster view

**Recommended layout: identity rail + tabbed evidence.** A 380 px left rail that never scrolls away, holding
the sequence object (logo, consensus repertoire, positional histogram, size, composition, score-vs-corpus);
tabs on the right for Annotations / Partners / Members / Genes.

The rail matters because the logo is the referent for everything in the tabs. Region-conditional variation is
cheap: on a protein cluster the rail swaps the positional histogram for a pLDDT distribution and nothing else
moves.

**The design must lead with the absent cases**, because they are half the data: 437 of 900 clusters have no
term at FDR < 0.05, 444 have no logo, 387 have no module, and 282 of 600 UTR clusters have zero partners
surviving the phylogenetic filter. Every one of those is a designed state with its cohort denominator printed,
never a blank panel.

*Known weakness to mitigate:* tabs hide the partner panel behind a click, and for the 437 no-term clusters the
partner panel *is* the evidence. Surface a partner count in the tab label and a pointer from the empty
annotation state.

*Alternatives considered:* evidence ladder (single column ordered by evidential strength) for the sceptical
reviewer; bilingual facing pages for the mRNA-design engineer; instance-first progressive zoom for readers
arriving from their own gene.

### R3 — Meta-module network view

**Recommended layout: level-of-detail cockpit** — a persistent 6×6 meta rail, a main canvas showing one module
at a time, and an inspector.

```
+--------------------------------------------------------------------------------------+
| (!) co-occurrence, not binding                                    [methods] [theme]  |
+------------+-------------------------------------------------+-----------------------+
| META RAIL  |  MAIN CANVAS (context: M5 selected)              | INSPECTOR             |
| (always on)|                                                  |                       |
| 6x6 module |  M5 intra: 24 protein x 33 UTR, 126 edges         | NODE prot_0072        |
|  P\U 1 2 3 4 5 6                                               |  [ sequence logo ]    |
|   1 |#|+|.| |+|.|   o--\                  []                   |  RGRGGG  cov .39      |
|   2 |+|#|+| |.| |       \-----------------[] <- utr5_0079      |  position N->C        |
|   3 |.|+|#|.|.|.|   o---/                 []                   |  |..||||.|||..|.|     |
|   4 | |.|.|#|.|.|                                              |  TOP TERMS            |
|   5 |+|.| | |#|.|   o------------\        []                   |   RNA-binding sf      |
|   6 |+|.|.| |.|#|                 \-------[]                   |     11.1x  FDR 6e-20  |
|            |                                                   |  PARTNERS 17          |
| cell=count |  [ ] show M5's 45 cross-module edges as stubs     |   utr5_0079  .517     |
| rows=prot  |  showing 57 of 519 nodes / 126 of 2,620 edges     |   [-> cluster page]   |
+------------+-------------------------------------------------+-----------------------+
```

The 6×6 matrix is a **matrix, not a node-link meta graph**, because the relationship is directional and
asymmetric — M1protein→M2utr is 178 edges but M2protein→M1utr is 66. A symmetric meta graph destroys that.
The main canvas draws one module at a time (max 133 nodes, M3), so a hairball is structurally impossible on
the default path.

Node glyphs carry the cluster's actual consensus logo, a coverage bar (the honesty mark), and a positional
sparkline — the published Fig 3e vocabulary, made interactive. Edges are solid when backed by a consensus-level
pair (1,430 of 2,620) and dashed when only cluster-level.

*Alternatives considered:* Fig 3e-faithful two-column bipartite for readers checking published pairs; a
seriated 201×318 adjacency matrix (4.10% dense, module blocks visible as diagonal blocks) for the sceptical
reader; six-panel small multiples for a talk audience; split-screen dual representation with brushed linking
for the analyst.

## 7. Open questions — two of these block work

**BLOCKING — a manuscript/data conflict.** The manuscript's only named M2 example reads "MLXIPL … contains the
M2 `utr3_0027` motifs." But `modules.json` assigns `utr3_0027` to **M1**, and the code that built that very
figure (`build_mlxipl_signatures.py`) uses **`utr3_0227`**. One of the three is wrong. This blocks all M2
narrative content and, more importantly, it is in the submitted manuscript.

**BLOCKING — an unreproducible figure claim.** The APEX localization result for M2 has lamina q = 0.725 and
OMM q = 0.551, which does not support the corresponding sentence in the text. Separately, the exact gene
partition behind Fig 4b (published n = 667 vs n = 460) cannot be reproduced from the `tf_modules`
intermediates, which hold 858 TFs split 447/411.

**Scope decisions:**
- Include the SOX2 design story (Figs 5–6)? Different audience, different data tree.
- Include mouse? 827,161 instances exist, but any-annotation coverage is 25.3% vs 63.9% for human.
- Hosting account — this must not be a personal GitHub account if the URL goes in the paper.

**Design risks to hold in view:**
- A narrative site makes statistical co-occurrence read as physical interaction more easily than a bare table
  does. The co-occurrence caveat is non-dismissible chrome over every partner panel.
- Sorting any edge table by `npmi_raw` regenerates the exact artifact leaderboard the analysis removed — 25 of
  the top 30 are ZNF clade artifacts, by the authors' own verdict column. Offer `npmi_raw` as a sort key in
  exactly one place: the paralogy page, where seeing the artifacts *is* the point.
- Half the site is a dead end for an arbitrary arrival: 387 of 900 clusters and 51.1% of transcripts have no
  module. Every one needs a designed empty state with its denominator.
- `plddt` is on a 0–1 scale, not 0–100.
